# ย้าย state มาไว้ใน Redux Toolkit และรับ build step ของ Vite

เดิมสถานะของหน้าอยู่ในตัวแปรระดับบนสุดของ `app.js` ห้าตัว แก้ตรงไหนก็ได้ และทุกจุดที่แก้
ต้องจำเองว่าต้องเรียกวาดใหม่ตรงไหนบ้างกับต้องเขียนลง `localStorage` เมื่อไหร่ พอเพิ่ม
กล่อง preview ที่มีปุ่มจำนวนชุดที่สอง จุดที่ต้องซิงก์ก็เพิ่มเป็นสามที่ — การ์ด กล่อง preview
และแถบยอดรวม

ย้ายมาใช้ Redux Toolkit ให้การเปลี่ยนสถานะทุกอย่างผ่าน action เดียวกันหมด แยกเป็นสาม slice
ตามอายุของข้อมูล: `order` (ต้องจำข้ามการเปิดเว็บ) `filters` (อยู่แค่ในหน้า) และ `ui`
(เรื่องของหน้าจอล้วน ๆ) การเขียนลงเครื่องย้ายไปอยู่ใน listener middleware ที่เดียว

RTK ไม่ได้ออกแบบมาให้โหลดผ่าน `<script>` ตรง ๆ จึงต้องรับ Vite กับ `npm install` มาด้วย
แลกกับการที่ double-click `index.html` แล้วใช้งานได้ทันทีซึ่งหายไป

ทางเลือกที่ไม่เอาคือเขียน store เล็ก ๆ เองด้วย `Object.freeze` กับ subscriber list
ซึ่งพอสำหรับงานขนาดนี้และไม่ต้องมี build step เลย แต่โปรเจกต์นี้เป็นโปรเจกต์ฝึก
การได้ใช้ของจริงที่ใช้ในงานสำคัญกว่าการประหยัดขนาด

## Consequences

- ต้อง `npm install` ก่อนถึงจะเปิดเว็บได้ และต้อง `npm run build` ก่อนเอาขึ้น production
  README กับ CLAUDE.md ต้องบอกเรื่องนี้ให้ชัด
- `node_modules/` กับ `dist/` เข้า `.gitignore` แล้ว
- **กฎ "กดเพิ่มจำนวนแล้วห้ามวาดลิสต์ใหม่ทั้งก้อน" ยังอยู่** และตอนนี้เปราะกว่าเดิม
  เพราะ `store.subscribe` ยิงทุก action วิธีรักษาคือ `sync()` ใน `main.js` เทียบว่า
  อะไรเปลี่ยนก่อนสั่งวาด โดยอาศัยว่า `createSelector` คืน reference เดิมเมื่อตัวกรองไม่เปลี่ยน
  ใครแก้ `sync()` ต้องตรวจซ้ำว่ากดเพิ่มจำนวนแล้วมีการ์ดถูกวาดใหม่ใบเดียวจริง
- รูปแบบข้อมูลใน `localStorage` ไม่เปลี่ยน ของที่ค้างอยู่จากเวอร์ชันก่อนอ่านต่อได้เลย
- Redux DevTools ใช้ได้ทันทีถ้าติดตั้งส่วนขยายไว้ `configureStore` เปิดให้เองในโหมด dev
